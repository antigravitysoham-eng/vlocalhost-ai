Vlocalhost runs on your machine, so we cannot see what went wrong unless you tell us. The app writes a short report you can read, check, and then send — or not.

Send us a diagnostic report

About a minute. Nothing leaves your machine until you send it.

1 · Generate it

Click Report a problem on the Record tab. It writes the report and opens the folder holding it. If the app will not start at all, run python vlocalhost.py --diagnose in the folder you installed to — same file.

2 · Read it

It is plain text: your settings, package versions, the error and the last lines of the log. No meeting audio, no transcripts, no notes, no file names. Home paths and your account name are replaced before it is written.

3 · Send it

Attach vlocalhost-report.txt to a GitHub issue or an email. Delete any line you would rather not share first — it is your file.

Raise a bug on GitHub Email us privately

🔒  We never collect anything automatically

Vlocalhost has no telemetry and no crash-reporting endpoint. There is no server for one to report to. The diagnostic report is a file on your disk, and sending it is an action only you can take.

Common problems

Worth trying before you write to us.

The installer says Python was not found
Install Python 3.9 or newer from python.org. On Windows, tick “Add python.exe to PATH” on the first screen — this is the single most common cause. Then run the installer again.
I used the ZIP and there is no desktop icon
Correct, and deliberate: the ZIP is portable. It writes nothing outside the folder you unpacked it into, which is why deleting that folder removes it completely. The folder ships two helpers — double-click Create desktop shortcut.cmd to add it to your desktop and Start menu, and Remove desktop shortcut.cmd to take it away. No registry writes, no admin rights, nothing outside your home folder.
Recording starts but no words appear
Check which source is selected in Settings → What to listen to. If you are on a call, choose both so the far end is captured as well as you. If you connected a headset after the app opened, press Refresh beside the microphone picker.
The transcript stops in a noisy room
It should not any more. Vlocalhost 1.2 replaced the voice detector: the previous one read steady background noise as speech, so an utterance never ended and nothing was written until you pressed Stop. If you are on an older build, updating is the fix.
Notes are empty but the transcript is fine
The summariser is a separate local model. Install Ollama and run ollama pull llama3.2. Transcripts are always saved even when summarising fails, so nothing is lost in the meantime.
